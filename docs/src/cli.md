# Документация модуля CLI

## 1. Обзор

Папка `src/cli` — это **точка входа** в приложение voice_ai. Она содержит тонкий CLI-слой на базе фреймворка [Typer](https://typer.tiangolo.com/), который:

- Разбирает аргументы командной строки
- Собирает конфигурацию, подменяя значения из CLI
- Передаёт управление доменным модулям (`src/core`, `src/llm`, `src/memory`)
- **Не содержит бизнес-логики** — только оркестрация

Модуль следует паттерну **тонкой точки входа** — это слой, который собирает все зависимости и запускает приложение.

### `__init__.py`

- **Размер:** 0 байт (пустой)
- **Назначение:** Делает `src/cli/` распознаваемым Python-пакетом. Ничего не экспортирует.

### `app.py`

- **Путь:** `src/cli/app.py`
- **Размер:** 213 строк
- **Назначение:** Всё CLI-приложение целиком. Определяет 4 команды для пользователя и внутренние вспомогательные функции.

## 3. Справочник команд

CLI предоставляет 4 команды через объект Typer:

| Команда | Функция | Строка | Описание |
|---------|---------|--------|----------|
| `run` | `run()` | 26 | Запуск полного голосового пайплайна (Микрофон → VAD → STT → LLM → TTS → Колонки) |
| `chat` | `chat()` | 84 | Текстовый чат без аудио (не нужен микрофон/колонки) |
| `models` | `models()` | 131 | Список доступных моделей Ollama |
| `show-config` | `show_config()` | 150 | Вывод всех 22 полей конфигурации |

**Точка входа:** `python -m src.cli.app <команда> [опции]`

**Примечание:** В `pyproject.toml` нет секции `[project.scripts]`. CLI запускается только через `python -m`.

## 6. Архитектурные паттерны

### 6.1 Группа команд Typer

**Где:** `app.py:10`

Один объект `typer.Typer()` объединяет 4 функции с декоратором `@app.command()`. Это стандартный паттерн Typer для CLI с несколькими командами.

### 6.2 Подмена конфигурации

**Где:** `app.py:38–53`, `app.py:90–93`

Опции CLI собираются в словарь `overrides`, затем используется для создания нового `Config(_env_file=None, **overrides)`, если есть переопределения. Если переопределений нет — используется синглтон `config`. Это чисто разделяет «использовать настройки по умолчанию/из env» и «CLI имеет приоритет».

### 6.3 Мост в async

**Где:** `app.py:63`, `app.py:94`, `app.py:144`

Каждая команда — это синхронная `def` (требование Typer), которая вызывает `asyncio.run(...)` для перехода в асинхронный мир. Вся реальная работа с вводом/выводом происходит в приватных `async def` функциях.

### 6.4 Ленивые импорты

**Где:** `app.py:101–102`

`PromptBuilder` и `ContextManager` импортируются внутри `_text_chat()`, а не в начале файла. Это позволяет не загружать эти модули для команд, которым они не нужны (например, `models` или `show-config`).

### 6.5 Предварительная проверка здоровья

**Где:** `app.py:71`, `app.py:105`

Команды `run` и `chat` вызывают `check_ollama_health(cfg)` до начала работы. Это даёт ранний сбой с понятным сообщением об ошибке, если Ollama недоступна.

### 6.6 Корректное завершение работы

**Где:** `app.py:75–79`

`_run_pipeline` использует `try/except/finally`, чтобы гарантировать вызов `pipeline.shutdown()`. Команда `run` ловит `KeyboardInterrupt` на верхнем уровне.

### 6.7 Валидация ввода на границе

**Где:** `app.py:49–52`

Опция `--mode` проверяется по белому списку `("button", "wake_word", "continuous")` до передачи дальше. Некорректные значения дают понятную ошибку и `typer.Exit(code=1)`.

## 7. Поток данных

### Поток выполнения команды `run`

```
Пользователь вводит: python -m src.cli.app run --mode wake_word
                              │
                              ▼
                      ┌───────────────┐
                      │  app.py:run() │  ← Typer отправляет сюда
                      │  (sync def)   │
                      └───────┬───────┘
                              │ собирает Config с подменами из CLI
                              │ настраивает логирование через _setup_logging()
                              │ запускает asyncio.run(_run_pipeline(cfg))
                              ▼
                    ┌─────────────────────┐
                    │ _run_pipeline(cfg)  │  (async)
                    └─────────┬───────────┘
                              │ проверяет Ollama: check_ollama_health(cfg)
                              │ создаёт пайплайн: create_pipeline(cfg)
                              │ запускает: pipeline.run()
                              │ завершает: pipeline.shutdown()
                              ▼
                ┌───────────────────────────┐
                │  Pipeline (src/core/)     │
                │  Аудио → VAD → STT → LLM │
                │  → TTS → Колонки          │
                └───────────────────────────┘
```

### Поток выполнения команды `chat`

```
Пользователь вводит: python -m src.cli.app chat
                              │
                              ▼
                      ┌────────────────┐
                      │  app.py:chat() │  ← Typer отправляет сюда
                      └───────┬────────┘
                              │ собирает Config
                              │ запускает asyncio.run(_text_chat(cfg))
                              ▼
                    ┌──────────────────────┐
                    │  _text_chat(cfg)     │  (async REPL-цикл)
                    └──────────┬───────────┘
                               │ проверяет Ollama: check_ollama_health(cfg)
                               │ цикл:
                               │   читает ввод пользователя из stdin
                               │   сохраняет сообщение в SQLite
                               │   строит промпт через PromptBuilder
                               │   стримит ответ через OllamaClient
                               │   печатает токены в stdout
                               │   сохраняет ответ ассистента в SQLite
                               │ выход по "выход" / "quit" / "exit"
```

## Итог

Папка `src/cli` — это минимальный, чётко сфокусированный слой точки входа, состоящий из двух файлов:

- **`__init__.py`** — пустой маркер пакета
- **`app.py`** — CLI на Typer с 4 командами (`run`, `chat`, `models`, `show-config`), служащий точкой сборки для всего приложения `voice_ai`

Не содержит бизнес-логики — только разбор аргументов, подмену конфигурации, мост в async и делегирование доменным модулям в `src/core`, `src/llm` и `src/memory`. Зависимости строго однонаправлены (CLI → домен), модуль запускается через `python -m src.cli.app`.
