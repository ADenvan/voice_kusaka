# Документация модуля LLM

## Обзор

Папка `src/llm` отвечает за взаимодействие с **большими языковыми моделями (LLM)**. Модуль предоставляет:

- **HTTP-клиент** для общения с локальным сервером Ollama (стриминг и обычный режим)
- **Сборщик промптов** — формирует системный промпт и список сообщений для LLM
- **Проверку здоровья** — валидация доступности Ollama перед запуском

Модуль следует паттерну **разделения ответственности**: один файл отвечает за транспорт, другой — за форматирование промптов.

---

## Структура файлов

```
src/llm/
├── __init__.py          # Пустой маркер пакета
├── ollama_client.py     # HTTP-клиент для Ollama

```

## Файлы

### `ollama_client.py`

Асинхронный HTTP-клиент для общения с локальным сервером [Ollama](https://ollama.com). Использует библиотеку `httpx`.

**Основные возможности:**
- Стриминг ответов токен за токеном (`chat_stream`)
- Обычные запросы с полным ответом (`chat`)
- Проверка доступности сервера (`is_available`)
- Список установленных моделей (`list_models`)
- Предстартовая валидация (`check_ollama_health`)

**Класс `OllamaClient`:**
- Принимает `Config` в конструкторе, извлекает параметры Ollama
- Переводит `httpx`-исключения в доменные (`LLMConnectionError`, `LLMTimeoutError`)
- Соответствует протоколу `LLMClient` из `src/core/protocols.py`

**Функция `check_ollama_health`:**
- Проверяет доступность сервера Ollama
- Убеждается, что настроенная модель установлена
- Выдаёт понятное сообщение об ошибке на русском языке

**Настройки из `Config`:**
- `ollama_base_url` (по умолчанию `http://localhost:11434`)
- `ollama_model` (по умолчанию `qwen2.5:7b`)
- `ollama_timeout` (60 секунд)
- `ollama_temperature` (0.7)
- `ollama_num_ctx` (4096 — размер окна контекста)
- `ollama_num_predict` (256 — максимум токенов)

**Экспорт:** `OllamaClient`, `check_ollama_health`.

---

### `prompt_builder.py`

Определяет системный промпт и собирает список сообщений в формате, который ожидает Ollama API.

**Системный промпт (`SYSTEM_PROMPT`):**
- Многострочная строка на русском языке
- Инструктирует LLM действовать как голосовой ассистент "voice_ai"
- Отвечать кратко, разговорным русским языком
- Избегать markdown и форматирования
- Никогда не использовать другие языки

**Класс `PromptBuilder`:**
- Хранит системный промпт (по умолчанию — модульная константа)
- Метод `build_messages(history)` добавляет системный промпт в начало истории диалога
- Возвращает список словарей `[{"role": ..., "content": ...}]`

**Особенности:**
- Полностью самодостаточный — не импортирует ничего из проекта или сторонних библиотек
- Чистая трансформация данных, без I/O

**Экспорт:** `SYSTEM_PROMPT`, `PromptBuilder`.

## Зависимости

### Внутренние зависимости (внутри `src/llm`)

Файлы **не зависят друг от друга** — они полностью независимы:

```
ollama_client.py  ──✗──►  prompt_builder.py
prompt_builder.py ──✗──►  ollama_client.py
```

Они собираются вместе потребителями (pipeline, CLI), а не друг другом.

### Исходящие зависимости (что импортирует `src/llm`)

| Откуда | Что импортирует | Где используется |
|--------|-----------------|------------------|
| `src.core.config` | `Config` | `ollama_client.py` — параметры подключения |
| `src.core.exceptions` | `LLMConnectionError`, `LLMTimeoutError` | `ollama_client.py` — доменные исключения |
| `httpx` | (библиотека) | `ollama_client.py` — асинхронный HTTP-клиент |

`prompt_builder.py` не импортирует ничего — полностью самодостаточен.

### Входящие зависимости (кто зависит от `src/llm`)

| Consumer | Что импортирует | Как использует |
|----------|-----------------|----------------|
| `src/core/pipeline.py` | `OllamaClient`, `PromptBuilder` | Основной голосовой пайплайн — стримит ответы LLM |
| `src/cli/app.py` | `OllamaClient`, `check_ollama_health`, `PromptBuilder` | CLI-команды: проверка здоровья, список моделей, текстовый чат |
| `tests/test_llm.py` | Все экспорты | Юнит-тесты для LLM-компонентов |
| `tests/test_memory.py` | `SYSTEM_PROMPT`, `PromptBuilder` | Тесты сборки сообщений в контексте памяти |

## Архитектурные паттерны

### Protocol-oriented design (структурная типизация)

`OllamaClient` соответствует протоколу `LLMClient` без явного наследования. `Pipeline` принимает любой объект, подходящий под `LLMClient`, что позволяет заменить бэкенд LLM.

### Dependency Injection

`OllamaClient` получает всю конфигурацию через объект `Config`, переданный в конструктор. Никакого глобального состояния или чтения переменных окружения внутри класса.

### Async-first

Все I/O-методы асинхронные. `chat_stream` возвращает `AsyncIterator[str]`, позволяя пайплайну обрабатывать токены по мере их поступления — критично для низких задержек в голосовом ассистенте.

### Exception translation

Сырые исключения `httpx` (`ConnectError`, `TimeoutException`) перехватываются и переводятся в доменные исключения (`LLMConnectionError`, `LLMTimeoutError`). Это изолирует потребителей от деталей HTTP-библиотеки.

### Single Responsibility

- `prompt_builder.py` — чистая трансформация данных (без I/O, без зависимостей)
- `ollama_client.py` — HTTP-транспорт и обработка протокола (без логики промптов)

### Fail-fast health checking

`check_ollama_health()` валидирует доступность сервера и наличие модели на старте, выдавая понятные сообщения об ошибках до начала обработки.

### Streaming by default

Пайплайн использует `chat_stream()` (не `chat()`) для минимизации времени до первого токена — важно для голосового ассистента, где воспринимаемая задержка имеет значение.

## Поток данных

```
Речь пользователя
    → STT-транскрипция
    → извлечение истории из SQLite
    → PromptBuilder.build_messages(history)     ← src/llm/prompt_builder.py
    → OllamaClient.chat_stream(messages)        ← src/llm/ollama_client.py
        → httpx POST в Ollama /api/chat
        → парсинг SSE-потока
        → yield токенов
    → токены собираются в ответ
    → сохранение в историю SQLite
    → TTS-синтез
    → воспроизведение аудио
```

## Тестирование

Тесты находятся в двух файлах:

- **`tests/test_llm.py`** — 6 тестов: `PromptBuilder` (дефолтный/кастомный промпт), `OllamaClient` (недоступный сервер, ошибки подключения для `chat` и `chat_stream`), `check_ollama_health`
- **`tests/test_memory.py`** — 3 дополнительных теста для `PromptBuilder` в контексте системы памяти

---

## Итог

`src/llm` — это модуль взаимодействия с LLM, разделённый на две независимые части:

- **`ollama_client.py`** — транспортный слой (HTTP-клиент для Ollama)
- **`prompt_builder.py`** — слой форматирования (системный промпт и сборка сообщений)

Модуль использует асинхронный стриминг для минимизации задержек, переводит исключения в доменные типы и соответствует протоколу `LLMClient`, что позволяет заменить бэкенд LLM без изменений в остальном коде.
